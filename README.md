# ตู้เซฟรหัสผ่าน (Password Manager)

เว็บแอปจัดการรหัสผ่านแบบ zero-knowledge ตู้เซฟถูกเข้ารหัสในเบราว์เซอร์ด้วย AES-256-GCM โดยใช้กุญแจที่สร้างจากรหัสผ่านหลักด้วย PBKDF2-SHA256 600,000 รอบ จากนั้นจึงส่งไปเก็บใน Supabase
**Supabase และ Netlify ไม่เคยเห็นรหัสผ่านหลักหรือข้อมูลที่ยังไม่เข้ารหัส**

| ส่วน | หน้าที่ |
|---|---|
| `src/` | แอป React + Vite ที่ย้ายดีไซน์มาจาก Figma Make "Design Vault Password Manager" |
| `src/lib/` | ส่วนที่ไม่เกี่ยวกับหน้าจอ: เข้ารหัส (`crypto.ts`), ซิงก์ Supabase (`sync.ts`), โมเดลข้อมูลและการวิเคราะห์ความปลอดภัย (`model.ts`), TOTP (`totp.ts`), ตัวสร้างรหัสผ่าน (`password.ts`) |
| `src/dev/mock-supabase.ts` | Supabase จำลองในหน่วยความจำ ใช้กับ `npm run dev:mock` เท่านั้น ไม่ถูกรวมใน build จริง |
| `vite.config.ts` | เปิดให้ frontend เฉพาะ `SUPABASE_URL` / `SUPABASE_ANON_KEY` กัน secret/service_role key และห้าม production build ด้วย mock |
| `supabase/migrations/` | ตาราง `vaults` พร้อม RLS (ผู้ใช้เข้าถึงได้เฉพาะแถวของตัวเอง) และ trigger ที่กันการเขียนทับข้อมูลที่ใหม่กว่า |
| `netlify.toml` | คำสั่ง build, โฟลเดอร์ publish และ security headers (CSP ที่อนุญาตให้คุยกับ `*.supabase.co` เท่านั้น) |

### รหัสผ่านเดียว (แบบ Bitwarden) และรหัสกู้คืน

ผู้ใช้มี**รหัสผ่านหลักตัวเดียว** เบราว์เซอร์แปลงเป็นกุญแจสองตัว (`src/lib/keys.ts`):

```
รหัสผ่านหลัก + อีเมล ─► PBKDF2-SHA256 600,000 รอบ ─► master key
master key ─► HKDF "login" ─► กุญแจล็อกอิน   (ส่งให้ Supabase Auth เป็นรหัสผ่านบัญชี)
master key ─► HKDF "wrap"  ─► กุญแจห่อ       (ไม่ออกจากเบราว์เซอร์)
```

ข้อมูลตู้เซฟเข้ารหัสด้วย**กุญแจตู้เซฟแบบสุ่ม** ซึ่งถูกห่อเก็บไว้ 2 ชุดในไฟล์เดียวกัน: ชุดหนึ่งห่อด้วยรหัสผ่านหลัก อีกชุดห่อด้วย**รหัสกู้คืน** (25 ตัวอักษรสุ่ม แสดงครั้งเดียวและอยู่ใน Emergency Kit)
Supabase เห็นแค่กุญแจล็อกอิน ซึ่งย้อนกลับไปเป็นกุญแจห่อหรือรหัสผ่านหลักไม่ได้

- **ลืมรหัสผ่านหลัก:** กด "ลืมรหัสผ่านหลัก?" → ลิงก์ทางอีเมล → กรอกรหัสกู้คืน → ตั้งรหัสใหม่ (ต้องมีทั้งอีเมลและรหัสกู้คืน) รหัสกู้คืนเดิมจะถูกเปลี่ยนใหม่ให้
- **ไม่มีรหัสกู้คืน:** กู้ไม่ได้ ใครก็ช่วยไม่ได้ รวมถึงผู้ดูแลระบบ
- **อีเมลเป็นส่วนหนึ่งของกุญแจ:** อย่าเปลี่ยนอีเมลของผู้ใช้ตรงใน Supabase Dashboard เพราะกุญแจล็อกอินจะไม่ตรงกับอีเมลใหม่ (แอปยังไม่มีฟีเจอร์เปลี่ยนอีเมล)
- **บัญชีจากยุคสองรหัสผ่าน:** อัปเกรดอัตโนมัติครั้งเดียวเมื่อปลดล็อก หรือผ่านลิงก์ "อัปเกรดบัญชี" ที่หน้าเข้าสู่ระบบ (ใช้รหัสผ่านบัญชีเดิม + รหัสผ่านหลักเดิม) ข้อมูลอยู่ครบ

## 1. ตั้งค่า Supabase

1. สร้างโปรเจกต์ที่ https://supabase.com/dashboard
2. ไปที่ **SQL Editor** แล้วรันไฟล์ `supabase/migrations/20261016000000_vaults.sql`
   หรือใช้ CLI:
   ```bash
   npx supabase link --project-ref <project-ref>
   ```
   ```bash
   npx supabase db push
   ```
3. ไปที่ **Authentication → Providers → Email** และ**ปิด "Secure password change"** (ค่าเริ่มต้นปิดอยู่แล้ว) เพราะแอปเปลี่ยนกุญแจล็อกอินผ่าน `updateUser` หลังผู้ใช้ยืนยันรหัสผ่านหลักแล้ว
4. ไปที่ **Authentication → URL Configuration**
   - ตั้ง **Site URL** เป็น URL ที่ผู้ใช้เปิดจริง ถ้ามีโดเมนของตัวเองให้ใช้โดเมนนั้น (ของเราคือ `https://pass.grocscode.com`) ไม่อย่างนั้นใช้ URL ของ Netlify เช่น `https://your-site.netlify.app`
   - เพิ่ม URL เดียวกันใน **Redirect URLs** (ทั้งลิงก์ยืนยันอีเมลและลิงก์ "ลืมรหัสผ่านหลัก" จะพากลับมาที่หน้านี้)
5. ไปที่ **Project Settings → API** แล้วคัดลอก **Project URL** และ **anon / publishable key**
   ⚠️ ห้ามใช้ `service_role` key ในหน้าเว็บเด็ดขาด

## 2. Deploy บน Netlify ผ่าน GitHub

1. Push repo นี้ขึ้น GitHub
2. ที่ Netlify ไปที่ **Add new site → Import an existing project → GitHub** แล้วเลือก repo นี้
   ค่า build จะถูกอ่านจาก `netlify.toml` อัตโนมัติ (`npm run build` และโฟลเดอร์ `dist`)
3. ไปที่ **Site configuration → Environment variables** แล้วเพิ่มค่า:
   - `SUPABASE_URL` = `https://<project-ref>.supabase.co`
   - `SUPABASE_ANON_KEY` = anon key
4. กด **Deploy** หลังจากนี้ทุกครั้งที่ push เข้า `main` ระบบจะ deploy ใหม่ให้เอง

## ฟีเจอร์

ใช้งานได้จริง: สมัคร/ล็อกอิน, onboarding พร้อม Emergency Kit, ปลดล็อกด้วยรหัสผ่านหลัก หรือด้วย Passkey (Face ID, Touch ID, ลายนิ้วมือ) ต่ออุปกรณ์, รายการ 6 ประเภท (บัญชีล็อกอิน บัตรเครดิต บันทึกลับ ข้อมูลส่วนตัว Wi-Fi บัญชีธนาคาร), โฟลเดอร์, แท็ก, รายการโปรด, ถังขยะ, รหัส 2FA (TOTP), ประวัติรหัสผ่าน, ตัวสร้างรหัสผ่าน/วลี/PIN, แดชบอร์ดตรวจรหัสอ่อน ซ้ำ และเก่า, ล็อกอัตโนมัติ, ล้างคลิปบอร์ดอัตโนมัติ, โหมดมืด, ส่งออก/นำเข้าไฟล์สำรองแบบเข้ารหัส, เปลี่ยนรหัสผ่านหลัก, ออกจากระบบทุกอุปกรณ์

ติดตั้งเป็นแอป (PWA): มี manifest ไอคอน และ service worker ที่ทำแค่หน้าออฟไลน์ (`public/sw.js`) ไม่ cache โค้ดแอปหรือข้อมูลตู้เซฟ ดูวิธีติดตั้งใน `USER_GUIDE.md`

นำเข้าเพิ่มเติม: Chrome CSV และ Bitwarden CSV (`login` / `note`) พร้อมดูตัวอย่าง ข้ามรายการซ้ำ และเข้ารหัสก่อนบันทึก ดูขั้นตอนและข้อจำกัดใน `USER_GUIDE.md`

ปลดล็อกด้วย Passkey (`src/lib/biometric.ts`): เปิดใช้ในตั้งค่า > ความปลอดภัย ขณะปลดล็อกอยู่ แอปสร้าง passkey ของเครื่องนั้นผ่าน WebAuthn และใช้ค่าลับจากส่วนขยาย PRF (ซึ่งตัวยืนยันตัวตนให้ออกมาเฉพาะเมื่อสแกนหน้าหรือนิ้วผ่าน) มาห่อกุญแจตู้เซฟเก็บไว้ใน localStorage ของเบราว์เซอร์นั้น ไม่มีอะไรเพิ่มใน envelope หรือส่งไป Supabase รหัสผ่านหลักยังใช้ได้เสมอและยังจำเป็นบนเครื่องใหม่ การออกจากบัญชีหรือลบตู้เซฟจะลบการตั้งค่านี้ในเครื่อง ส่วน passkey ใน iCloud Keychain / Google Password Manager ต้องลบเองในตั้งค่าของระบบ ต้องการ iOS 18 ขึ้นไป (ทั้ง Safari และแอปที่ติดตั้ง), Android Chrome รุ่นใหม่ หรือ macOS ที่มี Touch ID และการตั้งค่าแยกตามเบราว์เซอร์/แอปที่ติดตั้ง

ติดป้าย "เร็ว ๆ นี้": 2FA ของบัญชี, รายการอุปกรณ์, ตรวจรหัสที่รั่วไหล

ตู้เซฟที่สร้างด้วยเวอร์ชันก่อนหน้าจะถูกแปลงเป็นรูปแบบใหม่ให้อัตโนมัติเมื่อปลดล็อก

## หมายเหตุด้านความปลอดภัย

- anon key เปิดเผยในหน้าเว็บได้ เพราะ RLS เป็นตัวป้องกันข้อมูล และในฐานข้อมูลมีแค่ ciphertext
- การแก้ไขพร้อมกันจากหลายเครื่องจะถูกตรวจจับผ่านคอลัมน์ `version` ฝั่งที่บันทึกช้ากว่าจะถูกให้ปลดล็อกใหม่ แทนที่จะเขียนทับข้อมูลของอีกเครื่อง
- ควรกด "ส่งออก" เก็บไฟล์สำรองไว้เป็นระยะ ไฟล์ที่ได้ยังเข้ารหัสอยู่
